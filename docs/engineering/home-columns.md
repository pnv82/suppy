# Home column selection

Home's existing session-list heading has a Columns button. Its modal contains labelled checkboxes, Restore defaults, Cancel and Save. Selection is shared by desktop tables and narrow-screen cards, persists per trusted tenant and survives reload/restart. Escape cancels and returns focus. The default columns remain speed at cadence, Max speed (10 s), estimated DPS, TCS and heart rate; session identity, details and actions always remain available. No permanent toolbar row is added. An empty selection is valid.

Optional columns include a compact 5/10/20-minute speed group, distance, active time, elapsed time, board, session type, median speed, cadence, wind and data availability. Scope-sensitive speed/cadence/DPS/TCS/HR follow the existing Best 20 min / Whole session switch. The compound best-window column always uses its three exact continuous windows, with duration labels, goal matching and elapsed-boundary hints; missing windows never substitute historical summaries. Max and median remain whole-session references. Wind uses the existing presented session context, keeping source/coverage labels and athlete adjustments. No measurements are recalculated or edited by choosing columns. All values use the existing unit preference.

`set_home_columns({columns:[...]})` validates supported unique IDs through the shared domain catalog, stores them in canonical display order, and returns `homeColumns` in both REST/MCP dashboard state. Unknown fields/IDs, duplicates and tenant-spoofing are rejected. The server resolves the tenant. This is a mutable preference tool; it does not revise sessions or analyses. Schema 8 adds one JSON preference field; existing original uploads are unchanged.

Wide selections scroll inside the table while phone layouts show selected fields as cards. Row menus retain visible, keyboard-accessible actions. Existing latest-ten selection, trend chooser and comparison scopes remain independent of visible columns.
